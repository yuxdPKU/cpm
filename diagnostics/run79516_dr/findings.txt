Verified code on server agrees with the local implementation:
CPMReconstructionHelper::compute_pair translates each state by cluster-minus-voxel-center, solves PoCA, accepts based on poca.valid and DCA alone, and defines delta_r=voxel_radius-midpoint_radius.
compute_helix_poca initializes from unrestricted infinite-line PoCA; accepts initial paths within +/-100 cm. No midpoint-to-voxel locality criterion exists.
Finite dca sets valid=true before convergence. Exceeding the path window or exhausting iterations returns this valid result, and compute_pair ignores converged.
line_fallback uses unrestricted infinite lines and bypasses the helix path bound. Helix mode does not propagate the configurable min_sin_angle to its initializer or fallback.
These are confirmed acceptance/solver defects. The B3 files contain sums, not per-pair s/t, convergence, fallback flags, or opening angle; the separate contributions of each defect cannot be quantified from these files. A common inward crossing branch is consistent with the positive dR bias; an exact common-vertex explanation has not been proved per pair.
